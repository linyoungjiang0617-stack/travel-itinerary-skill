# 一键生成 · 省心旅行攻略

默认用简体中文。用户要求新旅行时，交付顺路的逐日计划、适合手机的可共享网站，以及简洁路线流程图图片；按用户本次要求调整范围。修改已有旅行时先读取其当前线上共享数据和最新代码，不用初始化数据覆盖用户修改。默认保留已有网址、共享进度与订单金额。

## 工作流程

1. 整理目的地、旅行日期及年份、人数、航班、已订住宿、预算、饮食和体力约束。优先从对话或现有记录取得；缺少阻碍路线的关键信息时提问，能合理假设的先继续并标注。用户主动要求逐项访谈时一次只问一个问题。
2. 查阅最新可靠资料，在可访问范围内参考地图、官方与商家资料，以及小红书、抖音、大众点评等平台的公开攻略和评价；不假定任何平台均可访问或已接入，交叉核验并优先官方和商家一手信息，核对具体门店、位置、营业时间、票价、交通、预订、住宿和航班。记录来源与核验日期；证据不足写待核实，不能把规划估算当成交报价或保证营业。天气按行程日期与实际所在地查阅可靠预报，标注来源、获取时间和预测范围；超出预报期或获取失败时明确显示，不编造远期天气。
3. 依据住宿和固定事项安排地理上连续的路线，尽量少折返、少搬行李，预留排队、交通和机场时间。结合用户体力为主要景点估计步行距离与耗时，设计休息及天气或精力备选，不重复安排无目的的项目。餐饮每节点最多三个当地候选，标首推；用户选过相同店或品类时提示，尊重实际选择。
4. 将时间、地点、交通、候选餐饮、住宿、费用与准备提醒整理成统一结构。检查次日衔接、固定时刻冲突、每日强度、价格重复计算和实际地理顺路；未知坐标、码头、营业状态要标明，不制造精确性。用户给出的订单与金额高于估计。
5. 按 [网站与数据架构](references/website.md) 生成或更新网站。应用现有可用的网站构建技能和发布流程；公开共享及访问范围以用户指示为准，不暗自改变。默认适配手机、两设备共享打卡、按实际打卡推进弹性事项、固定事项保持时间、每个实际地点提供导航、两人预算及人均，以及出发倒计时；天气数据可用时按每日目的地展示预报。若当前平台无法实现其中某项，说明限制，不能声称已经实现。
6. 根据最终保存的行程生成简洁路线流程图图片，日期和节点顺序必须与网站一致。优先一页可保存的高清 PNG，标主要预计时间、住宿、航班和需预订项目；注明随实际进度调整。图片不能自动同步，网站更新后按需重生成。若用户还要 PDF，调用可用 PDF 技能并嵌入中文字体、渲染检查。
7. 检查行程连贯、内容来源、费用、导航链接、打卡顺延、跨设备同步、移动布局和图片可读性。只修复可确认的问题。真实手机、微信、运营商网络或第三方服务未实测时明确说明；不把单元测试当成现实网络验证。给出网站和图片链接，以及未确认的关键事项。

保持用户偏好可调整：情侣可用柔和可爱手账风，酒店价格、作息、饮食、交通、预算和每日体力须遵照该次指示，不沿用上次旅行的具体地点、年份、订单或价格。
